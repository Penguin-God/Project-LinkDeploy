# LINK DEPLOY

Unity 6000.3.8f1 기반 2D 생산·물류 타워 디펜스 게임입니다. `0_Document`의 유효한 기획 문서와 새로 제작한 픽셀 아트를 사용합니다. **백로그.txt와 스테이지.xlsx는 사용하지 않았습니다.** 스테이지 수치는 `스테이지.csv`에서 가져왔습니다.

## 실행

- Windows: `Builds/Windows/LinkDeploy.exe`를 실행합니다. 같은 폴더의 `LinkDeploy_Data`와 DLL도 함께 있어야 합니다.
- Unity: `Assets/2_Scenes/SampleScene.unity`를 열고 Play를 누릅니다. 게임 오브젝트와 UI는 런타임에 자동 생성됩니다.
- 처음에는 **추천 배치로 시작**을 선택하면 2,000G 중 1,500G로 실제 생산·운송·방어 건물 8개를 짓습니다. 수동 건설도 가능합니다.
- 준비 중에도 생산이 진행됩니다. 타워 위 탄약 표시가 차면 스테이지 1 버튼을 누르세요.

## 조작

| 입력 | 동작 |
|---|---|
| 왼쪽 건물 카드 → 지도 클릭 | 연속 설치 |
| R | 설치 방향 / 선택 건물 회전 |
| B 또는 건축 모드 열기/닫기 | 건설 목록 표시 전환 |
| 우클릭 또는 ESC | 설치 취소 |
| 건물 클릭 | 상세 정보, 사거리 확인 |
| 건물 드래그 | 빈 칸으로 이동 |
| DEL 또는 회수 버튼 | 건물 회수, 투자 골드 반환 |
| SPACE | 일시정지 / 재개 |
| ×1 / ×2 버튼 | 진행 속도 변경 |
| 스테이지 버튼 | 해당 스테이지 전투 시작 |

## 규칙

- 생산 구역은 15×8칸이며 좌하단이 (0,0)입니다. (0,0), (7,0), (14,0)은 건설 불가능한 보급 입구입니다.
- 세 입구는 각각 별도의 3×2 타워 구역에 연결됩니다. 타워는 그 구역에서만 설치할 수 있습니다.
- 출력은 상하좌우 한 방향으로만 이동합니다. 입력은 어느 방향에서나 받습니다. 잘못된 재료, 꽉 찬 저장고, 끊긴 도로에서는 손실 없이 대기합니다.
- 보급 입구는 같은 구역의 호환 타워 중 탄약이 가장 적은 타워에 우선 공급합니다.
- 돌 → 돌 공장 → 동그란 돌 → 새총. 쇠 → 화살 공장 → 화살 → 궁수. 화살 + 동그란 돌 → 총알 공장 → 총알 → 총.
- 제련소의 효과는 중첩됩니다. 냉기 둔화 상한은 90%이며, 다른 탄종으로 조합할 때 강화 효과는 사라집니다. 제련소의 필터 버튼으로 받을 탄종을 선택합니다.
- 타워는 사거리 안의 가장 가까운 적을 선택하고, 기존 표적이 죽거나 사거리 밖으로 나갈 때 다시 선택합니다. 공격은 탄약을 소모하며 추적 투사체는 지정 표적에게만 피해를 줍니다.
- 전투 중에는 건설·이동·회수·강화·필터 변경을 할 수 없습니다. 정보 확인, 일시정지, 배속은 가능합니다.
- 한 마리라도 목적지에 도착하면 패배합니다. 전부 처치하면 보상과 다음 스테이지, 설정된 건물이 해금됩니다. 클리어한 스테이지를 다시 플레이해 골드를 얻을 수 있습니다.
- 자동 저장과 메뉴의 수동 저장을 지원합니다. 이어하기는 건설 준비 상태에서 시작합니다. 새 작전은 메뉴에서 초기화합니다.

## 데이터 수정

`Assets/Resources/LinkDeployCatalog.asset`를 Inspector에서 편집합니다. 시작 골드, 지도 크기, 건물 가격·한도·레시피·생산 속도·저장량·강화, 스테이지 적 수·체력·간격·속도·보상·해금 건물이 들어 있습니다. 기존 설정을 덮어쓰지 않도록 초기 생성 후에는 기본값을 다시 적용하지 않습니다.

`Link Deploy > Prepare project`는 초기 카탈로그 및 TextMesh Pro 리소스를 준비합니다. 모든 UI 텍스트는 기존 MaplestoryBold 폰트를 사용하는 TextMesh Pro입니다.

## 문서에서 비어 있거나 충돌하는 값

문서의 확정값과 구현 보완값은 `Documentation/IMPLEMENTATION.md`에 구분했습니다. 보완한 값은 모두 카탈로그에서 바꿀 수 있습니다. 이미지에 표시된 임의 수치(하트 20개, 10웨이브 등)는 규칙으로 사용하지 않았습니다.

## 검증 및 빌드

- `Link Deploy > Verify gameplay`: 도메인 규칙 검증. 결과는 `Artifacts/domain-verification.txt`에 저장됩니다.
- `Link Deploy > Build Windows game`: 검증 후 Windows 실행 파일을 생성합니다.
- 에디터가 닫혀 있으면 Unity 배치 모드의 `-executeMethod LinkDeployEditor.BuildWindows`로도 실행할 수 있습니다.
- 에디터가 열려 있으면 `Tools/editor-command.txt`에 `build`, `verify`, `prepare` 중 하나를 기록하면 유휴 상태에서 한 번 실행합니다. 결과는 `Artifacts/editor-job.txt`에 기록합니다.
- Windows 실행 파일의 `--smoke-test` 옵션은 별도의 임시 게임 상태로 실제 렌더링과 스테이지 1 승리를 확인하고 스크린샷 및 결과를 `Artifacts`에 저장합니다. 개인 저장 데이터를 바꾸지 않습니다.

## 구성

- `Assets/Scripts/Domain`: 순수 상태 전이, 생산·운송·전투, ScriptableObject 데이터 정의.
- `Assets/Scripts/Presentation`: 입력·TMP UI·스프라이트·연결 오버레이·사거리·효과음·저장.
- `Assets/Editor`: 프로젝트 준비, 게임 규칙 검증, 빌드.
- `Assets/Resources/Art`: 직접 생성한 건물·타워·몬스터 16종 아틀라스와 숲 요새 배경.
- `Documentation/ART-PROMPTS.md`: 내장 이미지 생성 도구에 사용한 최종 프롬프트.

배경은 플레이 가능한 구역에 맞춰 런타임 스프라이트 구간으로 배치합니다. 건물 본체와 입출력 포트, 운송 화살표는 별도 레이어로 표현합니다.
